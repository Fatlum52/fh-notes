Command  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Method calls must be  issued, delayed, queued, or undone independently of their sender . 
Context.  Systems needing task scheduling, macro recording, or undo/redo . 
Forces.  Decoupling requester from executor . 
Solution.  Encapsulate an action and its receiver in a  Command  object with a common  execute()  
interface . 
Consequences.  Enables queuing, undo, and flexible invocation; adds extra objects . 
Related.  Strategy, Memento, Composite.  
Uses.  GUI buttons, transactional job queues.

Data Transfer Object  (DTO) 
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Transferring many fine -grained data calls acros s layers causes latency . 
Context.  Distributed or layered systems . 
Forces.  Minimize remote invocations . 
Solution.  Aggregate related data into a serializable object passed in one call.  
Consequences.  Reduces network overhead but duplicates data structures . 
Related.  Value Object, Facade . 
Uses.  REST/GraphQL payloads, EJBs.

Adapter  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Two components must collaborate despite incompatible interfaces . 
Context.  Integrating legacy or third -party APIs . 
Forces.  Reuse existing code without modification . 
Solution.  Wrap th e adaptee in an adapter that implements the target interface and delegates calls . 
Consequences.  Enables reuse; adds one indirection layer . 
Related.  Bridge, Decorator, Proxy . 
Uses.  JDBC drivers, interface converters.

Strategy  
(4-BSc_SWA_Conditions_Significance -Solution , 6-BSc_SWA_Method_DomainDrivenDesign -Solution ) 
Problem.  Multiple algorithms exist for one task and must vary independently . 
Context.  Behavioural variation at runtime . 
Forces.  Avoid conditional logic and promote extensibility . 
Solution.  Define a family of interchangeable strategies implementing a common interfac e; context 
delegates execution . 
Consequences.  Adds flexibility; increases number of classes . 
Related.  State, Template Method . 
Uses.  Sorting, payment or compression algorithms.

Façade  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Complex subsystems overwhelm clients with many classes . 
Context.  Large  frameworks or APIs . 
Forces.  Reduce coupling and simplify use . 
Solution.  Provide a single high -level interface that wraps and coordinates subsystem components . 
Consequences.  Simplifies usage; may hide advanced features . 
Related.  Adapter, Mediator, Layers . 
Uses.  API gateways, persistence or logging libraries.

Event Sourcing  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Current -state persistence loses audit and history information . 
Context.  Systems requiring traceability or temporal reconstruction . 
Forces.  Balance auditability and performance . 
Solution.  Store every state- changing event and rebuild state by replaying them . 
Consequences.  Provides full audit trail; complicates queries . 
Related.  CQRS, Observer . 
Uses.  Banking ledgers, Git, Kafka event stores.

Publish -Subscribe (aka: Observer)  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Many objects need automatic updates when ano ther changes . 
Context.  Event -driven GUIs or distributed notifications . 
Forces.  Minimize coupling between sender and receivers . 
Solution.  Subjects maintain subscriber lists and notify them on state change . 
Consequences.  Supports dynamic subscription; can ca use update cascades . 
Related.  Mediator, Event Bus . 
Uses.  UI bindings, message brokers.

Proxy  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Access to an object must be controlled or extended transparently . 
Context.  Security, caching, or remote access . 
Forces.  Maintain identical interface for clien t use . 
Solution.  Provide a proxy implementing the subject interface that adds behaviour before/after 
delegating . 
Consequences.  Adds flexibility and interception; small runtime cost . 
Related.  Decorator, Adapter.  
Uses.  Virtual proxies, RMI stubs, AOP interce ptors.

Context  Object  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  Many collaborating components require shared environment data . 
Context.  Frameworks handling sessions, locales, or configurations . 
Forces.  Avoid global variables yet share context consistently . 
Solution.  Encapsulate contextual information in a single object passed explicitly . 
Consequences.  Improves testability; requires explicit propagation . 
Related.  Dependency Injection, Service Locator .

Reflection  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  A system must inspect or modify its own structur e at runtime . 
Context.  Plug- in frameworks, scripting, dynamic binding . 
Forces.  Balance flexibility and type safety . 
Solution.  Represent classes and methods as meta -objects manipulable at runtime . 
Consequences.  Enables dynamic adaptation; reduces performanc e.

Chain of Responsibility  
(6.1-BSc_SWA_WITH_WHAT_ArchitectureMeans_Overview ) 
Problem.  Multiple handlers may process a request without the sender knowing who will handle it . 
Context.  Event processing, UI handling, middleware pipelines . 
Forces.  Decouple senders from specific receivers . 
Solution.  Link handlers into a chain; each processes or p asses the request on . 
Consequences.  Flexible routing; harder debugging.  
Related.  Command, Decorator . 
Uses.  Servlet filters, exception chains.

Composite  
(6.1-BSc_SWA_WITH_WHAT_ArchitectureMeans_Overview ) 
Problem.  Clients must treat individual and composite objects uniformly . 
Context.  Hierarchical structures such as GUIs or file systems . 
Forces.  Uniform interface for parts and wholes . 
Solution.  Define a common component interface; composites forward operations to ch ildren . 
Consequences.  Simplifies recursion; can make constraints hard to enforce . 
Related.  Iterator, Decorator.  
Uses.  DOM trees, UI hierarchies.

Interpreter  
(4-BSc_SWA_Conditions_Significance -Solution ) 
Problem.  A language or grammar must be parsed and executed easily . 
Context.  Simple DSLs or configuration expr essions.  
Forces.  Flexibility vs. performance . 
Solution.  Represent grammar rules as class hierarchies; each node interprets itself.  
Consequences.  Easy extension; inefficient for large grammars . 
Related.  Composite, Visitor . 
Uses.  Expression evaluators, query  filters.

State 
(6-BSc_SWA_Method_DomainDrivenDesign -Solution ) 
Problem.  Object behaviour changes with internal state . 
Context.  Workflow engines, game objects . 
Forces.  Avoid complex conditional logic . 
Solution.  Represent each state by a separate class sharing a common interface; context delegates 
behaviour . 
Consequences.  Simplifies transitions; increases object count . 
Related.  Strategy, Flyweight . 
Uses.  TCP connection states, vending machines.

Context.  Frameworks defining processing s keletons .

Decorator  
(6.2-BSc_SWA_WITH_WHAT_ArchitecturePrinciples ) 
Problem.  Functionality must be extended dynamically without subclassing.  
Context.  Systems requiring runtime behaviour extension . 
Forces.  Preserve original interface and composability . 
Solution.  Wrap components in decorators implementing the same interface and add pre/post

Consequences.  Flexible layering; many small objects . 
Related.  Proxy, Composite .

Layers  
(8.1-BSc_SWA_WITH_WHAT_ArchitecturePatterns -MudToStructure , 8-
BSc_SWA_Means_ArchitecturePatterns -Solution ) 
Problem.  Mixing presentation, business, and technical logic causes rigidity . 
Context.  Large systems with clear concern boundaries . 
Forces.  Separ ation vs. performance overhead .

interfaces . 
Consequences.  Enhances modifiability; may slow communication . 
Related.  MVC, Microkernel . 
Uses.  3-tier web apps, OSI st ack.

(8.1-BSc_SWA_WITH_WHAT_ArchitecturePatterns -MudToStructure , 8-
BSc_SWA_Means_ArchitecturePatterns -Solution ) 
Problem.  Systems must be easily extensible without a ffecting a stable core . 
Context.  Product lines, plug- in platforms, OS kernels .

Related.  Reflection, Layers .

Abstract Factory Class  
 
Problem.  Classes depend on families of related objects that must vary together.  
Context.  Systems supporting multiple configurations or platforms . 
Forces.  Encap sulate creation logic and keep code independent of concrete types . 
Solution.  Define an interface for creating families of objects; implement concrete factories per 
variant . 
Consequences.  Promotes consistency; adds abstraction layer . 
Related.  Factory Method , Prototype . 
Uses.  GUI toolkits (Windows vs. Mac), data provider APIs.

Mediator  
 
Problem.  Many -to-many communication between components creates tight coupling.  
Context.  Collaborative UI widgets, chat systems.  
Forces.  Reduce dependencies while preserving coordination.  
Solution.  Introduce a mediator that centralizes interactions among components.  
Consequences.  Simplifies component logic; mediator can grow complex.  
Related.  Observer, Facade.  
Uses.  Dialog boxes, air- traffic -control simulations.
